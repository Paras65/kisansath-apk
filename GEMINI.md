# Antigravity AI Operational Rules — Kisan Saathi (फसल से लेकर बिक्री तक)

You operate within a constrained compute environment for the **Kisan Saathi (किसान साथी)** application (PWA & Android TWA). To optimize resource usage, prevent quota drain, and guarantee farmer reliability, you MUST strictly follow these 9 core operational rules:

1. **Strict Scope & Minimal Footprint:** Address ONLY the exact problem or feature explicitly requested. No unsolicited refactoring or package additions. Restrict file access strictly to relevant files. Keep outputs concise and direct. Stop after 2 failed attempts and ask for guidance.
2. **Explicit Confirmation for Commands (No Auto-Exec):** NEVER execute terminal commands (`npm`, `git`, build scripts) or destructive actions without explicit, in-line user confirmation first.
3. **DRY Architecture & Centralized Configuration:** Never duplicate calculation logic (NPK dosage, MSP calculations, Web Speech, unit conversions) across tabs. Encapsulate shared workflows in centralized services (`src/utils/`, `src/services/`, `src/data/`). Centralize all external portal URLs and API endpoints in `.env` / `appConfig.js` (Zero hardcoded domain literals).
4. **Enterprise Security & Zero-PII Offline Policy:** Adhere to OWASP / ISO 27001 standards. Service Worker (`sw.js`) and Cache Storage must NEVER store authenticated API responses, farmer PII, or financial records. Sanitize all form inputs against XSS. Purge session data completely on logout.
5. **Fear-Free, Zero-Paperwork UX (Farmer Psychological Safeguards):** Never use intimidating land-ownership, survey, or bureaucratic terms (e.g. "नया खेत जोड़ें", "खसरा नंबर", "जमीन जोड़ें") that trigger fears of land registration, tax scrutiny, or online fraud. All crop tracking MUST use friendly crop calendar phrasing (e.g. `📅 अपनी बुआई तारीख चुनें` / `📅 अपन बोवाई तारीख चुनव`) with explicit reassurance badges (`🔒 100% सुरक्षित • शून्य कागज़ात • कोई खसरा या ज़मीन का ब्यौरा नहीं चाहिए`). Support zero-login guest local crop calendar (`kisan_guest_crop_plot`) upfront.
6. **7-Dimension Lifecycle Edge-Case Synchronization (Seed to Mandi):** Whenever any crop model, sowing date, or stage changes, ALL interrelated upstream and downstream modules (`HomeTab`, `MeraKhetModal`, `CalculatorSchemesTab`, `CropDoctorTab`, `MandiTab`) MUST be updated synchronously across 7 dimensions:
   - *Future/Planned Dates (`daysElapsed < 0`):* Never show negative days; display pre-sowing terms (`बुआई से X दिन पूर्व • खेत तैयारी व बीजोपचार`).
   - *Sowing Day (`daysElapsed === 0`):* Display `आज बुआई/रोपाई का दिन` with basal nutrient alerts (DAP + Potash).
   - *Post-Harvest / Over-Aged (`daysElapsed > totalDays + 10`):* Automatically switch to post-harvest grain drying, Token Tuhar Hath Mandi sales at ₹3,100 MSP, and next rabi crop preparation, updating action links to Mandi.
   - *Variety Duration Scaling:* Adapt stage milestones dynamically to variety maturity durations (short, medium, late).
   - *Agro-Climatic Zone Specifics:* Dynamically adapt seasonal advisories by zone (Bastar Plateau early monsoon, Northern Hills winter frost/पाला warnings, Plains canal irrigation).
   - *Multi-Plot Priority:* Prioritize active unharvested crops on home dashboards over completed ones.
   - *Weather Interlocks:* Automatically suppress fertilizer top-dressing and chemical sprays during rain or high wind (>15 km/h) events.
7. **Farmer-Centric User Manual (`docs/USER_MANUAL.md`):** Every new or modified feature must be immediately and synchronously documented in `docs/USER_MANUAL.md` (including ToC). The manual is strictly for farmers, RAEO, and cooperative societies: describe everything in simple, practical Hindi/Chhattisgarhi. NEVER include technical code, backend API routes (`/api/...`), database logic, or cryptographic details.
8. **Dual PWA & Android TWA Harmony (Zero-Conflict):** Maintain 100% functional parity between Web PWA and native Android TWA (`in.co.init65.kisan`). Handle Android hardware back-button modal unwinding, native status bar theming (`#1b5e20`), and seamless offline fallbacks without web install banner clutter or WebView layout shifts.
9. **Synchronous 8-Target Release & Automated Tagging:** On every build or release:
   - Synchronously update version numbers across ALL 8 files: `package.json`, `public/version.json`, `public/manifest.json`, `twa/twa-manifest.json`, `src/config/appConfig.js`, `.env`, `server/routes/api.js`, and `docs/USER_MANUAL.md`.
   - Run mandatory pre-build lint verification (`npm run lint` / `oxlint`) to catch undeclared variables, undefined references, and scope errors before build.
   - Verify clean build via `npm run build` with zero errors.
   - Automatically create an annotated Git tag `v<version>` (e.g. `git tag -a v1.0.31 -m "Release v1.0.31 - <features>"`) and push with tags (`git push origin main --tags` and `git push public-apk main --tags`). NEVER wait for the user to remind you to tag.
